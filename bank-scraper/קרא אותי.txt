איפה להתקין — חשוב
--------------------
עותק המקור של הסקרייפר נשמר בתוך הפרויקט, כדי שלא יאבד ויהיה ברור איזו
גרסה עובדת. אבל *ההרצה בפועל* צריכה להיות מעותק שיושב מחוץ לכל תיקייה
שמסתנכרנת לענן (OneDrive / Dropbox / Google Drive) ומחוץ לתיקיית הפרויקט.

הסיבה: תיקיית secrets מכילה סיסמאות בנק בטקסט גלוי. ב-git הן מוגנות
(‎.gitignore‎ חוסם את secrets\ ואת runtime\), אבל סנכרון ענן וגיבוי אוטומטי
לא מסתכלים על ‎.gitignore‎ ויעתיקו אותן החוצה.

בפועל: מעתיקים את התיקייה הזו למשל ל-C:\bank-scraper\ במחשב הלקוח, ומריצים
משם. הפרויקט מחזיק את המקור; המחשב מריץ את העותק.


איך משנים את תיקיית הפלט
--------------------------
היא לא מקובעת בשום מקום בקוד. הכי פשוט:
   לחיצה כפולה על "שינוי תיקיית הפלט.bat"
   → נפתח פנקס רשימות → משנים את השורה האחרונה → שומרים (Ctrl+S) → סוגרים.

או ידנית: פותחים את "הגדרות.txt" ומשנים את השורה האחרונה.

סדר העדיפויות, מהחזק לחלש:
   1. הרצה עם -OutDir בשורת הפקודה (חד-פעמי, גובר על הכל)
   2. הנתיב שרשום ב"הגדרות.txt"
   3. אם אין כלום — out\report שליד הסקריפט

אם הנתיב שגוי או על כונן שלא קיים, הסקריפט עוצר בהודעה ברורה ואומר מה
הבעיה. הוא לא ישמור בשקט במקום אחר.


איפה מזינים שם משתמש וסיסמה
-----------------------------
בתיקייה  C:\bank-scraper\secrets\  — קובץ אחד לכל בנק. הקבצים כבר קיימים
וריקים; פותחים בפנקס רשימות, כותבים בין המרכאות, ושומרים.

  hapoalim.json    { "userCode": "קוד המשתמש", "password": "הסיסמה" }
  leumi.json       { "username": "שם המשתמש",  "password": "הסיסמה" }
  mizrahi.json     { "username": "שם המשתמש",  "password": "הסיסמה" }
  discount.json    { "id": "תעודת זהות", "password": "הסיסמה", "num": "קוד המשתמש" }
  pagi.json        { "username": "שם המשתמש",  "password": "הסיסמה" }

פאג"י (בנק 52) — אלה אותם פרטים שאיתם נכנסים ל-https://online.pagi.co.il.
שימו לב שזה ערך נפרד מ-beinleumi: פאג"י אמנם שייך לקבוצת הבינלאומי, אבל יש לו
עמוד כניסה משלו, וכניסה דרך beinleumi לא תגיע לחשבון הזה.

אלה בדיוק אותם פרטים שאיתם נכנסים לאתר הבנק. אם לא ברור איזה שדה זה מה —
להסתכל במסך ההתחברות של הבנק עצמו, השמות שם תואמים.

חשוב:
  - לא למחוק את המרכאות, את הפסיקים ואת הסוגריים המסולסלים. רק את התוכן
    שבין המרכאות.
  - בנק שלא משתמשים בו — פשוט להשאיר ריק. הוא ידולג בהודעה מתאימה.
  - אחרי מילוי הקבצים, הריצו את ה-BAT.


איך מריצים
-----------
1) הרצה ראשונה צריכה אינטרנט ולוקחת כמה דקות (מוריד Node ודפדפן).
   לחיצה כפולה על "משיכת תנועות מהבנק.bat".

2) ממלאים סיסמאות בתיקיית secrets (ר' למעלה).

3) התחברות ראשונה לכל בנק צריכה דפדפן גלוי. פותחים את ה-BAT בפנקס רשימות,
   מסירים את ה-REM משורת FIRSTRUN, מריצים, ומחזירים אותו למקומו.

4) מכאן — לחיצה כפולה על ה-BAT בלבד.

הרצה ידנית משורת פקודה (שימו לב: מקף אחד, לא שניים):
   powershell -ExecutionPolicy Bypass -File "bank-scraper-portable.ps1" -OutDir "C:\Projects-CRM\Torah-World\bank-XL"
   ...אפשר להוסיף:  -Bank hapoalim   -Show   -Days 60


כניסה ללא SMS — חשוב
----------------------
ההתחברות היא בשם משתמש וסיסמה בלבד, בדיוק כמו באתר הבנק. אין שום שלב
של קוד אימות בתהליך.

כדי שהבנק לא ידרוש אימות נוסף, הסקרייפר שומר לכל בנק פרופיל דפדפן קבוע
(בתיקייה runtime\profiles). כך הבנק מזהה בכל הרצה את אותו "מחשב מוכר" —
בדיוק כמו הדפדפן הרגיל בבית שנכנס בלי שאלות.

לכן:
  - אין למחוק את התיקייה runtime\profiles. מחיקתה = הבנק רואה מכשיר חדש.
  - במעבר למחשב אחר מעתיקים את *כל* התיקייה, כולל runtime — כך עוברים גם
    הפרופילים והבנק ממשיך לזהות את המכשיר.
  - אם בכל זאת הבנק מציג משהו חד-פעמי בהתחברות הראשונה (שאלת זיהוי,
    הודעה), מריצים עם ‎-Show, מאשרים בחלון פעם אחת — וזה נשמר.


אם הפועלים נופל על TIMEOUT (עמוד כניסה חדש)
---------------------------------------------
בתחילת 2026 הפועלים החליף את עמוד הכניסה, וספריית הגרידה טרם עודכנה
רשמית (יש תיקון בדרך). עד אז:

1. מריצים גלוי:   ... -Bank hapoalim -Show
   יש עשר דקות. אם הטופס לא מולא או לא נשלח לבד — משלימים את הכניסה
   *ידנית* בחלון (שם משתמש + סיסמה). ברגע שנכנסים, המשיכה ממשיכה לבד,
   והמכשיר נזכר לפעמים הבאות.

2. אם גם זה נכשל — מריצים אבחון:   ... -Bank hapoalim -Show -Diag
   נשמר צילום-מסך של מה שהבנק הציג ברגע הכשל ב-  out\debug\hapoalim-fail.png
   ולוגים מפורטים בקונסולה. עם הצילום אפשר לטפל נקודתית.


מה לבדוק בסיכום שמופיע בסוף כל הרצה
-------------------------------------
  "2 accounts in this login - split the file by account_number..."
      קריטי. חיבור אחד החזיר כמה חשבונות. חייבים לפצל את הקובץ לפי
      העמודה account_number לפני קליטה — חשבון אחד בכל יבוא. בלי זה
      תנועות אמיתיות נדחות בשקט ככפילויות ונעלמות.

  "dedup: N by bank id, M by hash fallback"
      by bank id  = זיהוי כפילויות אמין, מבוסס המזהה הרשמי של הבנק.
      hash fallback = הבנק לא סיפק מזהה. הזיהוי שם חלש ומסתמך על
      התיאור, שהבנק משנה לפעמים. אם M גבוה — כדאי לעבור ידנית.

  "skipped: pending=N"
      תנועות שעדיין לא נסלקו. במכוון לא נקלטות: הבנק עוד ישנה להן
      תאריך ותיאור, וקליטה עכשיו מבטיחה כפילות בהרצה הבאה.


הרצה אוטומטית לפי שעון
------------------------
אפשר לקבוע במערכת שעה וימים, והסקרייפר ירוץ לבד. ההגדרה נעשית במסך
   ניהול ← משיכה אוטומטית מהבנק
ולא בקבצים כאן.

איך זה מחובר, בקצרה:
   המערכת (אתר) כותבת   ->  תזמון-סקרייפר.json  בתיקיית הפלט
   scheduler.ps1 קורא אותו, מחליט אם הגיע הזמן, ומריץ
   scheduler.ps1 כותב    ->  סטטוס-סקרייפר.json
   המערכת קוראת אותו ומציגה מתי רץ, האם הצליח, ומה הפלט

למה בצורה הזו: אתר אינטרנט אינו יכול להפעיל תוכנה על המחשב ואינו רץ
כשהדפדפן סגור — הדפדפן חוסם את זה בכוונה, וזו הגנה נכונה. לכן החיבור
נעשה דרך קובץ משותף, ומי שמריץ בפועל הוא Windows.

התקנה — פעם אחת:
   לחיצה כפולה על "התקנת תזמון.bat".
   נרשמת משימה בשם OlamHaTorah-BankScraper שמתעוררת כל 15 דקות ובודקת
   אם הגיע הזמן. ברוב הפעמים היא לא עושה כלום ומסתיימת מיד.
   לא נדרשות הרשאות מנהל.

בדיקה בלי לחכות:
   powershell -ExecutionPolicy Bypass -File scheduler.ps1 -WhatIfOnly
      מדפיס מה היה קורה עכשיו, בלי להריץ ובלי לכתוב סטטוס.
   powershell -ExecutionPolicy Bypass -File install-schedule.ps1 -Status
      מראה אם המשימה מותקנת ומתי תרוץ.
   powershell -ExecutionPolicy Bypass -File install-schedule.ps1 -Remove
      מבטל את ההרצה האוטומטית. הרצה ידנית ממשיכה לעבוד.

מגבלות שחשוב להכיר:
   - המשימה רצה רק כשהמחשב דלוק והמשתמש מחובר אליו.
   - "משיכה עכשיו" מהמסך אינה מיידית: המתזמן מתעורר כל רבע שעה.
   - רצה פעם אחת ביום. אם המחשב היה כבוי בשעה שנקבעה, המשיכה תתבצע
     בפעם הראשונה שהמחשב יידלק באותו יום — ולא תדלג על היום.
   - הרצה שנכשלה אינה מנסה שוב מעצמה עד היום הבא. הכישלון מוצג במסך.


הבדיקות
--------
בתיקיית "בדיקות" — לחיצה כפולה על "הרצת הבדיקות.bat" (דורש Node מותקן;
הסקרייפר עצמו לא דורש, הוא מתקין לעצמו עותק פרטי).

הבדיקות רצות מול הקוד האמיתי שבתוך ה-PS1, לא מול עותק — אז אם מישהו
ישנה את הסקרייפר והבדיקות עדיין עוברות, זה אומר משהו.

מה הן מכסות:
  test-mapping.js   מיפוי השדות לחוזה של המערכת, וזיהוי הכפילויות.
                    כולל התרחיש המרכזי: הבנק משנה תיאור בין משיכות,
                    והתנועה עדיין מזוהה כאותה תנועה.
  test-accounts.js  שיוך תנועות לחשבון הנכון כשיש כמה חשבונות בחיבור.
  verscheck.ps1     בדיקת גרסת Node (הספרייה דורשת 22.22.2 ומעלה).


אזהרה — פרטי ההתחברות
-----------------------
הסיסמאות נשמרות בתיקיית secrets כטקסט גלוי לחלוטין, בהרשאות ברירת מחדל.
כל מי שיש לו גישה למחשב הזה יכול לקרוא אותן. זה לא תוקן.

בנוסף: מסירת סיסמת בנק לתוכנה היא הפרה של תנאי השימוש של הבנקים בישראל.
אם ייעלם כסף מהחשבון, הבנק עלול לטעון להפרת תנאים ולדחות אחריות.

המסלול החלופי, שלא דורש להחזיק סיסמאות בכלל: חוק שירות מידע פיננסי
תשפ"ב-2021 מחייב את הבנקים להעמיד את המידע דרך API בהסכמת הלקוח.
המערכת כבר בנויה לזה — ר' app/api/bank-sync.js ומיגרציות 074 ו-083.
